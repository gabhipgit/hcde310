What it is + why a designer might care (1 paragraph)
    Last.fm (https://www.last.fm/api/intro) is a music API that allows users to look at music data in general, as well as their own listening data. 
    It provides people the chance to build their own music related projects. A designer might care about this API because it lets them tinker with/access data from albums, artists, top charts, and their own user data to make a music related app that better gets across music related information that people want to see in an organized way. Beyond that, it also has methods for authentication, library, and tags that a designer can use to customize their app.

One working example: code + its output
The output of this code will print out the top 5 global tracks and their artist according to Last.fm's data. 

    ```python
    import os, requests
    from dotenv import load_dotenv
    load_dotenv()

    def lastfm(method, **params):
        r = requests.get("https://ws.audioscrobbler.com/2.0/", params={
            "method": method,
            "api_key": os.environ["LASTFM_API_KEY"],
            "format": "json",
            **params,
        })
        data = r.json()
        if "error" in data:
            raise Exception(f"Last.fm error {data['error']}: {data['message']}")
        return data

    # Global top tracks
    tracks = lastfm("chart.gettoptracks", limit=5)
    for t in tracks["tracks"]["track"]:
        print(t["artist"]["name"], "-", t["name"])
```

Gotchas: rate limits, missing data, confusing docs
    Rate limit:  cannot exceed 1000 queries a day (per API key). No more than 2 reference APIs.

    Missing data: Because a lot of last.fm's data comes from user input as well as external data providers, it's not promised that all data will be present or 100% accurate. 
    For example, there have been reports of image data missing from last.fm's api, or overall lacking in information for album data because of mismatched input. 
    Another thing to bring up, if one wanted to use last.fm to look at their own personal listening data(through the user param), they would have to link their last.fm account to their music streaming service. 

    Confusing docs:  The most confusing part about Last.fm's docs are that it's methods are on the left side bar rather than directly below the documentation page. Clicking on a method will give more detail about what it does as well as its params, authorization requirement status, sample repsonse, and error codes. 

Design angle: one project idea it enables, and one ethical or UX consideration
    Using Last.fm's API one could make a music related tracker that takes in a person's listening data and compare it to global charts to see where they land in popular music taste. We could also expand on this project by using weather data and seeing if there's any correlation between a users song choice and the weather pattern. One ethical consideration would be figuring out all the data that last.fm collects from the user and where it gets stored, or if it gets used in ways that users are not fully aware of. Another thing to consider is how long last.fm collects a users data and if there's a way to pause or stop it from doing so.
